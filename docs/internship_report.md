## 二、项目全流程体验

### 2.1 需求分析与方案设计（第一阶段）

作为项目的发起者和负责人，我首先进行了深入的需求分析：

- **业务需求**：用户需要一个直观的电影数据可视化平台，能够从多个维度了解电影市场的整体情况
- **功能需求**：需要包含大屏总览、基础查询、高级可视化三大模块
- **非功能需求**：页面响应速度快、支持多端适配、数据展示美观直观

基于需求分析，我设计了完整的技术方案：
- **架构选型**：前后端分离架构，前端负责展示，后端负责数据处理和API服务
- **技术栈确定**：Vue 3 + Vite（前端）、Flask + SQLAlchemy（后端）、MySQL（数据库）、ECharts（可视化）、Docker（部署）
- **模块划分**：前端按页面划分模块，后端按功能域划分路由模块

**学习收获**：在需求分析阶段，我深刻体会到"需求决定架构"的道理。一个好的架构设计必须基于清晰的需求分析，否则会导致后期大量的返工和重构。

### 2.2 数据采集与处理（第二阶段）

数据是大数据平台的核心，我完成了从数据采集到处理的完整链路：

- **爬虫开发**：编写Python爬虫程序，从豆瓣电影网站获取电影数据
- **数据入库**：将采集到的原始数据清洗后存储到MySQL数据库
- **ETL处理**：设计并实现数据抽取、转换、加载流程，建立聚合表结构

**关键技术点**：
- 使用requests库模拟HTTP请求
- 使用PyMySQL连接MySQL数据库
- 设计聚合表（agg_genre、agg_country、agg_year）预计算统计数据

**学习收获**：数据处理是大数据项目的基石。高质量的数据采集和清洗直接影响后续分析结果的准确性。聚合表的设计让我理解了"空间换时间"的性能优化思想。

### 2.3 后端API开发（第三阶段）

后端开发是连接数据与前端的桥梁：

- **Flask应用搭建**：初始化Flask项目，配置数据库连接
- **路由模块划分**：按功能域划分dashboard、movies、viz三个路由模块
- **API接口设计**：遵循RESTful规范，设计统一的请求响应格式
- **安全机制实现**：添加API Key认证和请求限流功能

**关键技术点**：
- SQLAlchemy ORM进行数据库操作
- Flask-Limiter实现请求限流
- CORS跨域配置

**学习收获**：API设计需要考虑易用性、安全性和可扩展性。一个好的API应该让前端开发者能够快速上手，同时具备足够的安全防护。

### 2.4 前端可视化开发（第四阶段）

前端是用户接触的第一界面，也是我投入精力最多的部分：

- **Vue 3项目搭建**：使用Vite初始化项目，配置路由和状态管理
- **大屏页面开发**：实现三栏响应式布局的大屏总览页面
- **高级可视化实现**：完成桑基图、矩阵树、词云等9种ECharts图表
- **组件封装**：封装可复用的EChart、UiCard、KpiBar等组件

**关键技术点**：
- Vue 3组合式API（`<script setup>`）
- ECharts图表配置和数据处理
- CSS Grid + Flexbox响应式布局

**学习收获**：前端开发不仅仅是实现功能，更要注重用户体验和代码质量。组件化开发能够大大提升代码的复用率和可维护性。

### 2.5 测试联调与问题修复（第五阶段）

测试是确保项目质量的关键环节：

- **单元测试**：对核心功能模块进行单元测试
- **接口联调**：前后端对接，验证API数据的正确性
- **问题排查**：定位并修复桑基图数据匹配、大屏布局自适应等问题
- **性能优化**：优化页面加载速度和接口响应时间

**学习收获**：测试不是可有可无的环节，而是开发过程中不可或缺的一部分。及时发现和修复问题能够避免后期更大的损失。

### 2.6 容器化部署与上线（第六阶段）

部署是项目从开发环境走向生产环境的最后一步：

- **Docker镜像构建**：编写Dockerfile，构建前后端镜像
- **Docker Compose编排**：配置docker-compose.yml，管理多容器服务
- **Nginx反向代理**：配置Nginx，实现静态资源服务和API反向代理
- **环境变量配置**：使用.env文件管理环境变量

**关键技术点**：
- Docker容器化技术
- Nginx配置和反向代理
- Docker Compose多容器编排

**学习收获**：部署是项目落地的关键。容器化技术能够保证开发环境和生产环境的一致性，大大简化部署流程。

## 四、核心技术难点与解决方案

### 4.1 桑基图数据匹配问题

**问题描述**：桑基图要求links中的source/target必须与nodes中的name精确匹配，但后端返回的年代节点name为数字类型，与links中的字符串类型不匹配，导致匹配失败，图表无法正常渲染。

**解决方案**：在前端数据处理阶段，将所有nodes.name、links.source、links.target统一转换为字符串类型，并增加节点存在性验证，过滤无效连线。

**代码位置**：[options.js](file:///d:/Ayueqian/project/code/douban-bigdata/frontend/src/echarts/options.js#L28-L73)

### 4.2 大屏布局自适应问题

**问题描述**：大屏页面在不同分辨率下布局效果不一致，高分辨率屏幕下出现大量空隙，影响视觉效果。

**解决方案**：采用固定宽度侧边栏+弹性中间区域的布局策略，使用`clamp()`函数限制列宽范围，并在不同断点下调整布局结构。

**代码位置**：[Dashboard.vue](file:///d:/Ayueqian/project/code/douban-bigdata/frontend/src/views/Dashboard.vue#L307-L358)

### 4.3 数据聚合性能问题

**问题描述**：直接从电影主表查询统计数据响应较慢，无法满足大屏实时展示需求。

**解决方案**：设计聚合表结构，预计算类型、国家、年份维度的统计数据，前端查询时直接从聚合表获取，提升响应速度。

**代码位置**：[models.py](file:///d:/Ayueqian/project/code/douban-bigdata/backend/models.py)
